THE BIG IDEA I LEARNED  (ReAct = "Reason + Act")
   - An AI model can only turn text into text. It can't actually DO anything, it
     forgets between messages, and it only knows things up to its training date.
   - So the LOOP has to live in MY code, not the model. The model SAYS what it
     wants to do (as text); my code DOES it and feeds the result back.
     Short version: "the model suggests, my code does."
   - The model should write its REASONING before choosing an action -- that makes
     its choices better. It's "thinking out loud," and that thinking shapes the
     next decision.
   - The loop is simple, the model is smart: my code does NOT judge whether the
     goal is met. It only checks "did the model say 'finish'?" The model decides
     it's done by choosing the "finish" action.
   - I don't write a question like "did I get the answer yet?" for every goal. I
     write ONE general rule ("if you have enough, finish; else use a tool") plus
     good tool descriptions, and the model works it out for any goal.

WHERE "SMARTS" COME FROM  (helps me pick models later)
   - A model learns to follow my format/rules during "instruction tuning," and
     learns good step-by-step judgment during "RLHF" (a training step). A tiny or
     untrained model skips these and breaks: first it ignores my format, then it
     stops or loops at the wrong time. The loop can USE smarts, not CREATE them.
   - Web search (RAG) gives the model better FACTS, but not better THINKING. Two
     different things.
   - A "judge" AI that double-checks the answer is a real, useful idea -- but it's
     for LATER. It is NOT how the loop stops.

WHAT I DESIGNED  (the action format, in spec.txt)
   - Two directions:
        What I send the model each turn (INPUT): goal, history so far, the tools
        it can use, the rules, and the answer format.
        What the model sends back (OUTPUT): action, args (details), reason. And to
        stop: action "finish" + the answer.
        The result of an action (OBSERVATION): success, tool, data, error -- the
        same shape as my Day-4 skill format.
   - Two ways the loop stops: the model says "finish", OR my code stops it after a
     set number of turns (so it can't run forever).
