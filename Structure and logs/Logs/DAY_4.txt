Day 4 Log
Date: 19 May, 2026

WHAT I DID (plain words)
I reorganized Orion so that adding a NEW skill later only means writing one new
file -- without touching the main decision code. Before, the orchestrator had
skill-specific logic baked in. Now every skill follows the same simple format,
so the orchestrator can treat them all the same way.

Files: web_search.py, response_synthesizer.py, orchestrator.py, test.py (new)

HOW IT WORKS
   - One rule for what EVERY skill must return:
        { skill name, success (true/false), data (the result), error (if any) }
     Same shape every time -> the rest of the code never needs special cases.
   - I wrapped the raw search function in a small "adapter" so it returns that
     standard shape.
   - The decision step now returns a LIST of skills (e.g. ["web_search"]) instead
     of a single yes/no -- so later it can ask for more than one at a time.
   - run() now loops through the chosen skills, runs each, collects all results in
     a list, and hands them to one prompt-builder that works no matter which
     skills ran.

WHAT WENT WELL
The test question "What is the latest AI news?" gave a clean, sourced answer. And
the structure is genuinely easy to extend now: adding a skill tomorrow just means
a new file + registering it -- no changes to the loop, prompt-builder, or decider.

PROBLEMS AND FIXES (lots of small ones)
   - Mixed up capital/lowercase keys (Success vs success) -- would silently break.
   - Forgot a "return", so a function gave back nothing in one case.
   - A filter made "found nothing" look the same as an error.
   - Used a {} where I needed a [] (a dict instead of a list).
   - On failure I stored a plain error string instead of the standard shape --
     would crash the next step.
   - Called a plain function as if it were attached to the class (self.) -- error.
   - My memory used my own format instead of the standard {role, content} one --
     fine now, but would block multi-turn chat later.
   - The search function hides its own errors, so I can't tell "found nothing"
     from "all engines broke." Noted it and moved on.

WHAT I LEARNED
   - Adapter pattern: keep the raw, reusable function, and wrap it thinly to fit a
     specific need.
   - "Open to add, closed to change": good structure lets you ADD features without
     editing old files.
   - Keep formatting code next to the data it formats.
   - Make every result the same shape -- it kills whole classes of bugs.
   - Senior habit: keep checking the real inputs/outputs of what you call, instead
     of coding from memory.
   - Even with search results, the AI can still make things up -- something I'll
     fix later with self-checking.

WHAT'S INCOMPLETE
Hints for skills, proper logging (still print()), saving memory to a file, the
"hides its own errors" search issue, and some old/dead prompt functions left over.

WHAT'S NEXT (Day 5 plan at the time)
