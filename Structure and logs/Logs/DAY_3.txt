Day 3 Log
Date: 17 May, 2026

WHAT I DID (plain words)
I built the "orchestrator" -- the part of Orion that decides what to do, runs it,
and keeps track of the conversation. Before, I used a fixed keyword list to decide
whether to search. Now I let the AI itself decide.

Files: orchestrator.py (new), groq_client.py (updated),
       assistant_service.py (slimmed down)

HOW IT WORKS
   - orchestrator.py has three main parts:
        setup          : loads the AI, the list of skills, and a memory list.
        _decide_skills : asks the AI "does this question need a web search?" and
                         makes it answer in a strict format (JSON).
        run            : the full pipeline -> decide -> search if needed ->
                         build the prompt -> get the answer -> save to memory.
   - I updated groq_client.py so I could fix the "temperature" and force JSON
     answers (more reliable).
   - assistant_service.py became a thin layer that just passes the question on.

WHAT WENT WELL
The AI picked the right choice for clear questions ("What is recursion?" -> no
search; "Latest AI news" -> search). Forcing JSON stopped formatting glitches.
If the AI's decision failed, it defaulted to searching (safe).

PROBLEMS AND FIXES
   - The AI sometimes answered "yes" (text) instead of true (a real yes/no value),
     which my code misread. I added a check that the answer is a real true/false,
     not text.
   - No checks on the AI's JSON -> a wrong key would crash things. Added checks.
   - My error-catching was too broad (even caught Ctrl+C) -> made it specific.
   - I stored the same skill twice -> fixed to one place.
   - Extra spaces in my prompt got sent to the AI -> removed them.

WHAT I LEARNED
   - Use temperature 0 for decisions, so the same question always gets the same
     answer.
   - Forcing JSON helps but isn't enough -- you still have to check the output,
     because the AI sometimes returns text instead of true/false.
   - "Defense in depth": several small checks, each catching a different mistake.
   - One job per file: orchestrator decides, service forwards, skills do the work.
   - I failed a review question about the "yes" vs true bug -- spotting sneaky
     edge cases is a skill I'm still building.

WHAT'S INCOMPLETE
Memory is lost when the program closes; only Groq supported; still using print()
instead of proper logging.

WHAT'S NEXT (Day 4)
Make adding a NEW skill a one-file change instead of editing the orchestrator
each time. Have the decision step return a LIST of skills.
