PROJECT ORION – 3-MONTH GOAL
(Long-term multi-year vision lives in Long_term_vision.txt — that is the north
star. THIS file is the actionable target for the next 3 months.)

================================================================================
THE GOAL IN ONE SENTENCE
================================================================================
In 3 months, Orion becomes a CLI "secondary developer" — an agent that can read
my codebase, answer questions about it, make file edits, run commands/tests,
observe the results, and iterate — grounded by web search and a light memory,
with multi-LLM routing and a safety gate.

This is the concrete, useful slice of the Year-1 "Build the Brain" goal. It
deliberately EXCLUDES voice, desktop control, multi-agent systems, and
production infra. Those come later.

================================================================================
WHY THIS SCOPE
================================================================================
The current code is a single-shot Q&A pipeline (decide -> run skills once ->
answer). A real developer assistant needs a LOOP: plan -> act -> observe ->
re-plan. Turning that loop on, plus the file/shell/code-search skills, is what
converts Orion from "a chatbot with search" into "a junior pair-programmer."
Everything in this 3-month plan serves that.

================================================================================
MONTHLY MILESTONES
================================================================================

MONTH 1 — THE LOOP + CORE SKILLS  ("make it an agent, not a Q&A bot")
  Definition of done:
  - orchestrator runs a plan -> act -> observe loop with a max-iteration cap.
  - Skills: file_read, file_write (gated), shell (gated), code_search (glob+grep).
  - Human-in-the-loop approval gate for any write/delete/shell action.
  - Conversation memory survives a multi-turn session.
  - Replace print() with real logging.
  Proof: "Read X, add function Y, run the tests" works end-to-end on this repo.

MONTH 2 — CODEBASE COMPETENCE + MEMORY  ("make it understand MY project")
  Definition of done:
  - Code navigation good enough to answer "where is X / what calls Y" via
    glob+grep+read (NO embeddings yet).
  - File-backed project memory (JSON or SQLite): decisions, facts, file notes.
  - Multi-LLM clients behind one interface (Groq + OpenAI + 1 more), with a
    simple router (cheap model classifies/plans, strong model reasons over code).
  - Eval harness: 8-12 fixed tasks Orion should pass; run them on every change.
  Proof: Orion explains an unfamiliar file correctly and recalls a past decision.

MONTH 3 — GROUNDING + POLISH + DEMO  ("make it trustworthy and shippable")
  Definition of done:
  - Light RAG over docs/code, but ONLY if grep proved insufficient (stretch).
  - Token/cost logging per request (foundation for later cost routing).
  - Robust error handling; no crashes on bad LLM output or failed tools.
  - A clean README + a recorded demo of Orion completing a real coding task.
  - Optional stretch: tiny web UI (Gradio/Streamlit) or Ollama local model.
  Proof: a stranger can clone, run, and watch Orion fix a bug in a sample repo.
