TASK 1 — The `Tool` dataclass  (this is where you learn Callable)
----------------------------------------------------------------
CONCEPT — Callable:
  A type hint is just a label saying what a field holds:
     name: str        -> holds text
     count: int       -> holds a number
     run: Callable    -> holds a FUNCTION (something you can call with () )
  The detailed form  Callable[[dict], Observation]  reads as:
     "a function that takes a dict and returns an Observation"
  It is ONLY a label. It does nothing by itself. (A function is a value in
  Python — you already passed one around during injection: get_next_output held
  your stub. Storing one in a dataclass field is the same idea.)

BUILD (put this in schemas.py, near your other dataclasses):
  from typing import Callable

  @dataclass
  class Tool:
      name: str
      description: str
      run: Callable[[dict], Observation]

  Remember: when you create a Tool, you pass the function BY NAME, no ():
      Tool(name="file_read", description="...", run=file_read)   # run=file_read, NOT file_read()
  Later you CALL it with ():  some_tool.run({"path": "..."})

SELF-CHECK (in a scratch test):
  from skills.file_read import file_read
  t = Tool(name="file_read", description="reads a file. args: {path}", run=file_read)
  print(t.name, "->", t.description)
  print(t.run({"path": "App/main.py"}))   # should print a success Observation
  -> If t.run({...}) returns the same Observation as calling file_read directly,
     you understand Callable. Done.

TASK 2 — The tool registry
----------------------------------------------------------------
CONCEPT:
  ONE dict mapping name -> Tool. Single source of truth. Two consumers:
    - build_prompt reads each tool's .description (to tell Groq its options)
    - the loop reads .run (to actually run the chosen tool, later)
  Adding a tool later = add ONE entry here. Nothing else changes. (Open/Closed.)

BUILD (a registry; put it where the orchestrator can reach it — e.g. top of
orchestrator.py, or a small tools.py you import):
  from skills.file_read import file_read

  TOOLS = {
      "file_read": Tool(
          name="file_read",
          description='reads a file. args: {"path": "<file path>"}',
          run=file_read,
      ),
  }

  NOTE: "finish" is NOT in here. finish has no function to run — it is a special
  signal the loop handles itself. You only register REAL, runnable tools.

SELF-CHECK:
  for name, tool in TOOLS.items():
      print(name, "->", tool.description)
  print(TOOLS["file_read"].run({"path": "App/main.py"}))   # success Observation
  -> One line per tool, and dispatch via the dict works. Done.

TASK 4 — Implement Groq (the "brain")
----------------------------------------------------------------
CONCEPT:
  Build the function that turns the prompt into a real decision: build prompt ->
  call Groq -> parse its JSON -> return an Output. Groq's output is UNTRUSTED
  (trust boundary), so parse it defensively.

BUILD (a method on Orchestrator — it needs self.llm):
  - First, give the orchestrator the registry in __init__:  self.tools = TOOLS
  - Then:
      def _groq_brain(self, state) -> Output:
          prompt = build_prompt(state, self.tools)
          response = self.llm.generate(prompt, temperature=0, json_mode=True)
          try:
              data = json.loads(response)
          except Exception:
              return Output(action="finish", reason="could not parse model JSON",
                            args={}, answer="(parse error)")
          return Output(
              action=data.get("action", "finish"),
              reason=data.get("reason", ""),
              args=data.get("args", {}),
              answer=data.get("answer"),
          )
  (Use .get() with defaults — do NOT do Output(**data); that breaks if Groq adds
   or drops a key. Defensive reading = trust boundary. Pydantic upgrade is later.)
  Imports you'll need in orchestrator.py: json (already there), Output (already
  there), build_prompt from response_synthesizer, and TOOLS / Tool.

SELF-CHECK (this spends a real Groq API call — your GROQ_API_KEY must load):

  state = AgentState(goal="Summarize what App/main.py does")
  print(agent._groq_brain(state))
  -> You should see a real Output: Groq's reasoning, action="file_read",
     args={"path": ...} (or similar). THAT is Orion making its own first decision.
